# 3、编写 Player 脚本

选择 Player 节点，为其添加脚本

![image.png](http://image-blog-001.test.upcdn.net/images/202605282315426.png)

使用默认

![image.png](http://image-blog-001.test.upcdn.net/images/202605282316641.png)

编写脚本

```gd
extends Area2D

@export var speed = 400
var screen_size
```

使用 `@export` 标注的变量可以在检查器中进行编辑，编辑器中如果赋值会覆盖脚本的值

```gd
func _ready():
	screen_size = get_viewport_rect().size
```

当**节点进入场景树**的时候，`_ready()` 函数会被调用，此时我们查看游戏窗口大小

接下来使用 `_process()` 函数定义玩家的行为，`_process()` 函数每一帧都会被调用，可以用来更新我们希望经常变化的游戏元素，通常执行如下操作：

- 检查输入
- 沿给定方向移动
- 播放合适的动画

输入动作在项目设置中的“输入映射”下定义，先输入一个动作 move_right，并进行添加

![image.png](http://image-blog-001.test.upcdn.net/images/202605282332330.png)

然后为这个动作分配按键

![image.png](http://image-blog-001.test.upcdn.net/images/202605282334712.png)

在事件那边按键盘上的方向键，会监听，选中后确定

![image.png](http://image-blog-001.test.upcdn.net/images/202605282335584.png)

此时，完成按键和动作的绑定

![image.png](http://image-blog-001.test.upcdn.net/images/202605282337894.png)

继续补充剩余几个方向的内容

![image.png](http://image-blog-001.test.upcdn.net/images/202605282339651.png)

继续，回到脚本，使用 `Input.is_action_pressed()` 检测是否按下了某个按键，按下会返回 `true`，否则返回 `false` 

```gd
func _process(delta: float) -> void:
	var velocity = Vector2.ZERO
	if Input.is_action_pressed("move_right"):
		velocity.x += 1
	if Input.is_action_pressed("move_left"):
		velocity.x -= 1
	if Input.is_action_pressed("move_down"):
		velocity.y += 1
	if Input.is_action_pressed("move_up"):
		velocity.y -= 1
	
	if velocity.length() > 0:
		velocity = velocity.normalized() * speed
		$AnimatedSprite2D.play()
	else:
		$AnimatedSprite2D.stop()
```

`Vector2.ZERO` 对应的是（0，0）向量，因为默认情况下玩家不移动
然后根据 `if` 分支去每帧检验用户的输入，这里根据方向分为 `x` 和 `y` 两个维度，如果同时按右和下，则对应（1，1）向量，表示右下

此时斜向移动速度会快于水平，因此需要进行**归一化**处理，即将速度长度设置为 1，再乘上想要的速度（对应方向的单位向量）

`$` 是 `get_node()` 的简写，`$AnimatedSprite2D.play()` 等同于 `get_node("AnimatedSprite2D").play()`

根据 `velocity.length()` 判断角色是否需要移动，如果需要就 `play()`，不需要就 `stop()`

现在有了运动方向，接下来需要更新玩家的位置
`clamp()` 一个值意味着将其限制在给定范围内，此时，角色是可以移动的

```gd
position += velocity * delta   # 每一帧时间以固定速度移动
position = position.clamp(Vector2.ZERO, screen_size)   # (0,0) 到屏幕右下角
```

![screen009.gif](http://image-blog-001.test.upcdn.net/images/202606060018892.gif)

`_process()` 的 `delta` 参数是帧长度，即完成上一帧所花费的时间，使用这个保证移动不会被帧率变化影响

## 3.1、选择动画

现在在角色可以动的基础上为其提供正确的动画
最初我们的 walk 动画对应的是向右走，此时需要对各个方向进行适配

![image.png](http://image-blog-001.test.upcdn.net/images/202606072229794.png)

因此，向左就水平翻转，用到 `flip_h` 属性

除此以外，我们也有 up 动画，此时默认向上的，那么向下也需要通过 `flip_v` 进行垂直翻转 

![image.png](http://image-blog-001.test.upcdn.net/images/202606072232967.png)

```gd
if velocity.x != 0:
	$AnimatedSprite2D.animation = "walk"
	$AnimatedSprite2D.flip_v = false    # 水平方向都是正向的人物
	$AnimatedSprite2D.flip_h = velocity.x < 0
elif velocity.y != 0:
	$AnimatedSprite2D.animation = "up"   # 上下的动画对称，无关水平
	$AnimatedSprite2D.flip_v = velocity.y > 0	
```

水平方向有速度时，`flip_h` 根据速度进行水平翻转，同样的，垂直方向也是

![screen010.gif](http://image-blog-001.test.upcdn.net/images/202606072241549.gif)

在这之后，将 `hide()` 添加到 `_ready()` 中，在游戏开始时隐藏玩家

```gd
func _ready() -> void:
	screen_size = get_viewport_rect().size
	hide()
```
## 3.2、准备碰撞

需要为检测何时被敌人击中做准备，这时要用到**信号**，在 `extends Area2D` 之后添加信号的定义

```gd
signal hit  # 定义一个 hit 信号
```

接下来，需要在敌人和玩家发生碰撞时，发出这个 hit 信号

选中 `Player` 节点，在检查器那里可以看到定义的 `hit` 信号

![image.png](http://image-blog-001.test.upcdn.net/images/202606072303426.png)

判断条件时和敌人发生碰撞，由于敌人将会用 `RigidBody2D` 节点，所以需要用到 `body_entered(body: Node2D)` 信号，物体接触玩家会发出这个信号

选择并进行连接

![image.png](http://image-blog-001.test.upcdn.net/images/202606072307454.png)

![image.png](http://image-blog-001.test.upcdn.net/images/202606072308562.png)

```gd
func _on_body_entered(body: Node2D):
	hide()
	hit.emit()
	$CollisionShape2D.set_deferred("disabled", true)
```

敌人每次击中玩家时发出一个信号，需要禁用玩家的碰撞检测，避免多次触发 `hit` 信号（使用 `set_deferred()` 使 Godot 等待可以安全禁用时生效，避免直接禁用导致错误）

最后再添加一个函数，用于在开始游戏时重置玩家

```gd
func start(pos):
	position = pos
	show()
	$CollisionShape2D.disabled = false
```
